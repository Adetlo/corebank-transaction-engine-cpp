# ADR-0001: C++20 as the language baseline

**Status:** Accepted (2026-10-14)

## Context

The engine needs cooperative thread cancellation, exact value types with cheap
comparisons, and a small amount of compile-time tabulation. It also needs to build
with the system compilers available on current Linux distributions and on macOS
without extra package managers. The CI matrix in `.github/workflows/ci.yml` uses GCC
and Clang on `ubuntu-latest`; local development happens on AppleClang.

C++23 would offer `std::expected`, but at the time of the decision it was not
uniformly available across those toolchains, and depending on it would narrow the
set of machines that can build the repository.

## Decision

Set `CMAKE_CXX_STANDARD 20` with `CMAKE_CXX_EXTENSIONS OFF` in `CMakeLists.txt` and
use C++20 features where they remove code rather than add novelty:

| Feature | Where it is used |
|---|---|
| `std::jthread` and `std::stop_token` | worker pool in `src/application/transaction_processor.cpp`; acceptor and per-connection threads in `src/messaging/tcp_server.cpp` |
| `std::condition_variable_any::wait(lock, stop_token, pred)` | `include/corebank/application/bounded_queue.hpp` |
| Designated initialisers | `Account`, `Transaction`, `Posting`, `BatchRun`, `ProcessorStats` construction throughout `src/` |
| `std::span` | `AccountLockManager::lock_exclusive(std::span<const AccountId>)` |
| `std::string::starts_with` | `src/cli/args.cpp`, `src/cli/commands_ops.cpp` |
| `<=>` and defaulted comparisons | `Identifier<Tag>`, `CurrencyCode`, `BusinessDate`, `Money::compare` |
| `requires` clause | `JsonWriter::number` template in `include/corebank/infrastructure/json_writer.hpp` |
| `std::chrono::sys_time`, `year_month_day` | `include/corebank/domain/time.hpp`, `src/domain/time.cpp` |
| `std::barrier` | `tests/concurrency/concurrent_idempotency_test.cpp` |
| `[[nodiscard]]` on every `Result` and accessor | all headers under `include/corebank/` |
| `constexpr` tables | currency table in `src/domain/currency.cpp`, `kBatchStages` in `include/corebank/domain/batch.hpp` |

`std::expected` is replaced by a hand-written `Result<T>` in
`include/corebank/domain/result.hpp` (see [ADR-0007](0007-error-handling.md)).

Platform differences are isolated in `cmake/CompilerWarnings.cmake`:

```cmake
function(corebank_platform_flags target)
  if(CMAKE_CXX_COMPILER_ID STREQUAL "AppleClang")
    target_compile_options(${target} PUBLIC -fexperimental-library)
    target_link_options(${target} PUBLIC -fexperimental-library)
  endif()
endfunction()
```

Apple's libc++ ships `std::jthread` behind that flag; GCC 13 and Clang 18 on Linux
need nothing. The same file enables `-Wall -Wextra -Wpedantic -Wshadow -Wconversion
-Wsign-conversion -Wold-style-cast` and more, with `-Werror` on by default.

## Consequences

Positive:

- Cancellation is uniform: every blocking wait in the engine takes a `stop_token`, so
  shutdown never needs sentinel values or polling flags.
- Value objects get correct ordering and equality from one `= default` line.
- Strong warnings plus `-Werror` catch narrowing and sign errors in money code at
  compile time.

Negative:

- macOS builds depend on an experimental library flag that Apple may change.
- `Result<T>` must be maintained in-house and offers fewer combinators than
  `std::expected`.
- Contributors need a C++20-capable compiler; older distributions cannot build the
  project.

## Alternatives considered

| Alternative | Why rejected |
|---|---|
| C++17 | No `jthread`, no `stop_token`, no `<=>`, no designated initialisers; the cancellation and value-type code would be longer and easier to get wrong. |
| C++23 | `std::expected` and `std::print` would help, but toolchain coverage was uneven, especially on AppleClang. |
| C++20 with a third-party `expected` library | Adds a dependency for one small type; `Result<T>` is 80 lines. |
| GNU extensions (`CMAKE_CXX_EXTENSIONS ON`) | Would hide portability problems between GCC and Clang. |
